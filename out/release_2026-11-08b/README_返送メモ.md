orig01_compare の 3 つの状態：
- **before**：修正前のバンク（48kHz で保存）を、修正前と同じく 44.1kHz として読む。音量の均しなし
- **pitch_only**：修正後のバンク。音量の均しなし（音程の修正だけの効果）
- **after**：修正後のバンク＋音量の均し（今のエンジン。pitch_only との差が、音量の均しの効果）

すべて同じ楽譜データから作り直しました。曲全体を速くして合わせることはしていません。

結果：
- **修正前**：9 経路すべて -131〜-143 cent（A=440 でも A=432 でも同じ）
- **修正後**：+4〜+15 cent
  - 修正前後の差は 146.0〜147.0 cent で、理論値 146.7 cent と一致しました
  - 修正後に残るずれは、録音そのもののピッチと考えられます。ただし、元の録音の測定はしていません
- **A=432 にかかる回数**：1 回だけ（`dsp.midi2hz`）
- **二重補正**：なし
  - 修正は、サンプルを保存するときのレート 1 か所だけです
  - 元の録音はすべて 44.1kHz なので、修正後は準備の段階でレートを変換していません
  - 演奏するときは、音の高さを合わせる再サンプリングを、楽器ごとに 1 回だけ行います
- **見つかった例外**：`jazz._bass_note`（ジャズのコントラバス）は、A の設定を使っていません。そのため A=432 の行は +44 cent になります
  - j01 は A=440 で作ったので、作った動画には影響しません。直すかどうかは未定です
- **音程を合わせない打楽器**：トライアングルとタンバリンは、音程の計算をしていません。修正前は、再生が約 8.8% 遅く・低くなっていました

再実行：`PYTHONHASHSEED=0 python3 verify_pitch.py --old-banks <修正前のバンク> --out <出力先>`
修正前のバンク（約 800MB）は Claude の作業場所にあるだけで、ZIP にもリポジトリにも入れていません。
