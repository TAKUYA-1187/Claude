# 写真 → カレンダー登録

写真から予定を読み取って Google カレンダーに登録します。
**登録・変更・削除は、毎回ユーザーのOKをもらってから行います。**

## 前提

- 書き込み先は **Google カレンダー**（Google Calendar コネクタ、`mcp__Google_Calendar__*`）。
  iPhone の「カレンダー」アプリに Google アカウントを追加しておけば、iCloud の予定と並んで iPhone にも表示される。
- iCloud カレンダーに直接書き込みたい場合は、Mac の Claude デスクトップアプリでコンピュータ操作を使う（このスキルの対象外。頼まれたらそう案内する）。
- タイムゾーンは Asia/Tokyo。ユーザーが別のタイムゾーンを明示しない限り、`timeZone` は指定しない。

## 手順

### 1. 写真を読み取る

写真に写っている予定を1件ずつ抜き出す。項目は次の通り:

| 項目 | ルール |
|---|---|
| 日付 | 年の記載がなければ今年。今日より過去の月なら来年の可能性があるので **❓をつけて確認**。曜日が書いてあれば日付と一致するか照合し、ずれていれば❓ |
| 開始・終了 | 終了時刻がなければ空欄にして確認（勝手に1時間と決めない）。時刻がなければ終日予定 |
| タイトル | 写真の表記をそのまま使う。短く要約しない |
| 場所 | 書いてあれば入れる |
| メモ | 持ち物・注意事項など、上に入らない情報 |

- 和暦（令和8年＝2026年）、「〜」「−」の期間、「午後3時」などは正しく変換する。
- 手書きやピンぼけで読めない文字は推測で埋めず、**❓をつけて「読めませんでした」と書く**。
- 予定でないもの（ヘッダー、注釈、ロゴなど）は入れない。
- 写真が複数あれば全部まとめて1つの表にする。

### 2. 重複を調べる（読み取りのみ）

`list_events` で対象期間の既存の予定を取得し、同じ日時・似たタイトルの予定があれば「重複の可能性あり」と印をつける。

### 3. 確認表を見せて、OKを待つ

次の形式で見せる。**この時点では何も登録しない。**

```
📷 写真から N 件の予定を読み取りました（登録先: Google カレンダー <アカウント>）

| # | 日付 | 時間 | タイトル | 場所 | メモ | 注意 |
|---|---|---|---|---|---|---|
| 1 | 11/3（火） | 10:00〜12:00 | 〇〇説明会 | 市民会館 |  |  |
| 2 | 11/8（日） | 終日 | 運動会 | 小学校 | 雨天時11/9 | ❓雨天順延日も登録しますか |
| 3 | 11/12（木） | 15:00〜❓ | 面談 |  |  | ❓終了時刻が読めません |

登録してよいですか？
- 「全部OK」→ そのまま登録
- 「1と3だけ」→ 番号を指定して登録
- 「2は14時から」など → 修正して表を出し直します
```

- ❓の項目が残っている予定は、ユーザーが答えるか「そのままでいい」と言うまで登録しない。
- 修正があったら、表を出し直してもう一度OKをもらう。

### 4. 登録する

OKが出た予定だけを、1件ずつ `create_event` で登録する。

- `summary` / `startTime` / `endTime`（ISO 8601、オフセットなし）/ `location` / `description`
- 終日予定は `allDay: true`
- `attendees` は付けない、`notificationLevel: "NONE"`（他人に招待メールを送らない）
- リマインダーはカレンダーの既定（`useDefaultReminders` は指定しない）
- `description` の末尾に「（写真から登録）」と入れておく

### 5. 結果を報告する

```
✅ 3件を登録しました
| # | 日付 | 時間 | タイトル | リンク |
...
取り消したい予定があれば番号を教えてください（削除前にもう一度確認します）。
```

登録に失敗した予定は、エラー内容と一緒にはっきり伝える。

## 絶対に守ること

- 確認表を見せる前に `create_event` / `update_event` / `delete_event` を呼ばない。
- 既存の予定の変更・削除は、たとえ重複に見えても、対象を示して個別にOKをもらってから行う。
- 読めなかった内容を推測で埋めない。
