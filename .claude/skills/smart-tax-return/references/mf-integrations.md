# マネーフォワード クラウド確定申告のデータ連携

会計士から「◯◯の連携を解除してください」と言われたときに見る場所と、その判断基準。

## 連携一覧を開く

```
https://accounting.moneyforward.com/accounts
```

ログイン済みなら「登録済一覧」が開く。見出しは「明細を自動取得する連携サービス」。
事業所セレクタが右上にあるので、複数事業所がある場合は対象を確認する。

## 一覧を機械的に読む

行はテーブルなので普通にDOMから取れる。Driveと違って仮想スクロールではない。

```js
const rows = Array.from(document.querySelectorAll('table tr'))
  .filter(r => r.querySelectorAll('td').length > 3);
rows.map((r, i) => {
  const td = r.querySelectorAll('td');
  const name = (td[0].innerText || '')
    .split('\n')
    .filter(x => x.trim() && !x.includes('連携サービスのサイト'))[0] || '';
  return (i + 1) + '. ' + name.trim() + '  |取得:' + (td[4] ? td[4].innerText.trim() : '');
});
```

対象サービスが「無いこと」を確認したいときは、本文全体を検索するほうが確実。
行の描画漏れや表記ゆれに引っかからない。

```js
const t = document.body.innerText;
({
  楽天市場: /楽天市場|my ?Rakuten/i.test(t),
  Yahoo: /Yahoo|ヤフー/i.test(t),
  さとふる: /さとふる/.test(t),
  Amazon: /Amazon|アマゾン/i.test(t),
})
```

## 解除してよいかの判断

会計士の依頼はたいてい条件付きで来る。

> 重複記帳を防ぐため、銀行やクレジット連携でも利用履歴が判断できるようでしたら解除をお願いします

つまり「その買い物が別の連携で捕捉できるなら、通販サイト側の連携は要らない」という意味。
だから解除する前に、**その通販サイトの決済がどのカードか**、**そのカードがMF連携されているか**を確認する。

| 通販サイト | 主な決済手段 | 連携状況の確認先 |
|---|---|---|
| 楽天市場（my Rakuten） | 楽天カード | 一覧の「楽天カード」 |
| Yahoo!ショッピング | PayPayカード | 一覧の「PayPayカード_◯◯」 |
| Amazon | AMAZONマスター（三井住友） | 一覧の「三井住友カード (VpassID)」 |

カード側が連携済みなら解除して差し支えない。連携していないカードで払っていた場合は、
解除すると履歴が追えなくなるので、会計士に確認してから。

「さとふる」のように**事業と無関係**という理由の依頼は、条件を確認する必要がない。

## 解除は設定変更なので必ず確認を取る

連携解除は取り消しに再認証が要る。ユーザーの明示的な指示があってから実行する。
指示があっても、**解除対象の一覧を提示して合意を取ってから**動かすのが安全。

会計士のメールを転送されただけの状態は「解除してよい」の合意ではない。
ユーザー本人が「解除して」と言ったかどうかで判断する。

## 既に解除済みだった場合

このワークフローでは実際にそうだった。過去のチェックリストに「解除作業中」と書かれていた項目が、
実際に一覧を見たら既に消えていた。

その場合は「作業しました」ではなく「**確認したところ既に解除済みでした**」と正確に報告する。
根拠として、現在の連携件数と内訳（銀行◯件・カード◯件）を添えると会計士が検証しやすい。

## メルペイ・メルカードについて

会計士の指摘①には、連携解除とは別に次の依頼が混ざっていることがある。

> メルペイを利用して仕入など経費を支払ったり、メルカードの返済を行った場合は、
> 『購入（その他取引）シート』に取引内容をご記入ください

メルペイ・メルカードはMF連携一覧に出てこないことが多く、**利用の有無をこちらでは判断できない**。
Driveにも該当資料がなければ、それは「利用がなかった」証拠にはならない。

必ずユーザー本人に確認する。「利用はありませんでした」と勝手に書かない。
