# せどり実務ノート 運用マニュアル

ブログ運営の方針・手順・記事計画は、すべてこのファイルにまとめる（ChatGPT時代の管理表・実行記録・運用メモは置き換え済み）。

---

## 1. なぜ方針を変えたか

| 問題 | 事実 | 対応 |
| --- | --- | --- |
| WordPress.com の停止 | WordPress.com の利用規約は「アフィリエイトへの送客を主目的とするブログ」や「検索エンジン向けに書かれたブログ」を禁止している。12サイト＋機械生成の下書き量産は、この規約に正面から当たる | 再審査はしない。通っても同じ運用なら再停止される。月間PVは3サイト合計で約28と少なく、失う資産はほぼない |
| AIが公開まで届かない | ChatGPTはWordPressへのログインで止まり、ファイルは増えたが公開0件・収益0円だった。Claudeのクラウド環境からも WordPress.com には接続できない | 記事をこのリポジトリに書いて push すれば、Cloudflare Pages が自動で公開する仕組みに変えた。**Claudeが執筆から公開まで1人で完結できる** |
| テーマの分散 | 家族・ペット・EC道具の3テーマは、運営者の実体験に基づいていない | 運営者が実際にやっている**買取せどり**の1サイトに集中する。自作の価格比較ツールと、経理の自動化という実データがあり、他のブログにない一次情報になる |

## 2. 仕組み

```
Claude が記事を書く（blog/src/content/posts/*.md）
  → ローカルでビルド・スマホ幅の表示確認・計算検証
  → git push（main または claude/nifty-thompson-99o7m3）
  → 公開先に自動で反映
       A. WordPress（自分のサーバー）：GitHub Actions が REST API で投稿 … wordpress/README.md
       B. Cloudflare Pages：Astro の静的サイトをそのまま公開 … 「3. オーナーがやること」の ①-B
```

**公開先は A・B のどちらか1つだけにする。** 両方で公開すると同じ記事が2つのURLに載り、検索エンジンに重複と見なされる。
オーナーの希望により **A（WordPress）を第一候補**にする（2026-09-23）。記事の書き方・管理はどちらでも同じ。

- サイト本体：Astro（静的サイト）。表示が速く、サーバー代0円
- 標準装備：目次、PR表記（`pr: true` で記事冒頭に表示＝ステマ規制対応）、構造化データ、サイトマップ、RSS、運営者情報、プライバシーポリシー、お問い合わせ
- 設定の変更箇所は `src/site.config.ts` の1か所だけ（サイト名・URL・運営者名・お問い合わせURL）

### ①-A WordPress で公開する（最優先・約40分）

手順は [wordpress/README.md](../wordpress/README.md) にまとめた。サーバー契約 → 初期設定 → プラグイン → 投稿用ユーザー → GitHub に3つの値を登録、の順。
**WordPress.com（〜.wordpress.com）は使わない**（規約でアフィリエイト主目的のブログが禁止。以前の停止の原因）。

### ①-B Cloudflare Pages で公開する（WordPress にしない場合・約10分）

アカウント登録だけでは公開されない。次の手順で「このリポジトリの記事を公開する設定」を作る。画面の表示名は多少違うことがある。

1. Cloudflare のダッシュボードで、左メニューの「Workers & Pages」（または「Compute (Workers)」）を開く
2. 「作成」（Create）を押し、「Pages」タブを選ぶ
3. 「既存の Git リポジトリをインポート」（Import an existing Git repository）を押す
4. 「GitHub に接続」を押す。GitHub の画面に移ったら「Install & Authorize」を押す（対象は「All repositories」でも、`Claude` だけを選んでもよい）
5. リポジトリ一覧から `Claude` を選び、「セットアップを開始」（Begin setup）を押す
6. 次の4か所だけ入力する（ビルドコマンドと出力先は、プリセットを選ぶと自動で入る）

   | 項目 | 値 |
   | --- | --- |
   | プロジェクト名 | `sedori-note` |
   | 本番ブランチ | `claude/nifty-thompson-99o7m3` |
   | フレームワーク プリセット | `Astro` |
   | ルートディレクトリ（「詳細設定」「Advanced」の中） | `blog` |

7. 「保存してデプロイ」（Save and Deploy）を押す

終わったら、Claude に「接続した」と伝える。ビルドの成否は Claude が GitHub 側から確認できる。公開URLは通常 `https://sedori-note.pages.dev`。プロジェクト名が使えず別の名前にした場合は、その名前を伝える。

### ② ASP にサイトURLを登録する（① の後）

A8.net・もしもアフィリエイトに登録したサイトURLが WordPress.com のもの（停止中）なら、審査に落ちるため新しいURLに変える。

- A8.net：管理画面の「登録情報」→「サイト情報の登録・変更」
- もしもアフィリエイト：管理画面の「サイト管理」（サイト追加）

メニュー名は変わることがある。見つからない場合は、画面の表示を Claude に送れば案内する。

その後、もしもで「Amazon」「楽天市場」のプロモーションに提携申請する。

### ③ お問い合わせフォーム（完了）

Googleフォームを作成し、`/contact/` に埋め込み済み（2026-09-23）。
フォームのURLは `src/site.config.ts` の `contactUrl` にある。差し替えるときはそこだけ変える。

- 回答は運営者管理のスプレッドシートに蓄積し、新規回答はメール通知される
- 回答管理スプレッドシートのURLは**このリポジトリには置かない**（公開リポジトリのため）
- プライバシーポリシーに、Googleフォームを利用していることを明記済み

**未検証**: 外部の読者が実際に送信できるかは、シークレットウィンドウでフォームを開き、
テスト送信してスプレッドシートに行が増えることを確認する（Claudeの環境からは
docs.google.com に接続できないため確認できない）。

### ④ ChatGPT の定期タスクを止める（完了）

「ブログ365日・月100万円｜重点3サイト日次運用」「WordPress復旧監視」ともに停止済み（2026-09-23）。

## 4. 収益化ロードマップ

月100万円は、自分の商品を持つ上位ブロガーの水準。アフィリエイトだけでは届きにくいため、段階ごとに収益源を積み上げる。

| 段階 | 目安 | やること | 収益源 |
| --- | --- | --- | --- |
| 1 | 記事1〜15本 | 基礎記事で「買取せどり」の検索を取る。ASP登録 | Amazon・楽天の商品リンク |
| 2 | 記事15〜40本 | 独自ドメイン・AdSense。高単価の比較記事 | クレジットカード、会計ソフト（A8.net） |
| 3 | 記事40本〜 | 月次の実績公開で信頼を積む。メール・LINE登録 | 高単価案件＋リスト |
| 4 | 記事1本目から並行 | note で仕入れ判定シート（980円〜）を販売し、全記事の最後で案内する。感想がたまったら値上げ・上位商品 | 自社商品（ここが月100万円の本線） |

投稿ペースは**週2〜3本**にする。1日に大量投稿すると、WordPress.com 停止と同じ「機械生成の量産」と判定され、Googleの検索順位も落ちる。本数より、一次情報と正確な数字で勝つ。

## 5. note で売る自社商品（ブログとの連携）

note の調査（ChatGPT で実施）の結論：売れているのは長文ではなく「具体的な問題を短時間で解決できる一次経験＋テンプレート＋判断基準」。
note の長く読まれる記事の流入は検索が中心なので、**検索はブログで取り、テンプレートを note で売る**分担にする。

```
検索 → ブログの無料記事（計算ツール・手順） → 記事の最後の案内 → note の有料テンプレート → 上位商品・メンバーシップ
```

| 商品 | 価格 | 状態 | ファイル |
| --- | --- | --- | --- |
| 買取せどりの仕入れ判定・入金管理シート（Excel） | 980円（感想3件で1,480円へ） | 原稿・Excel完成。オーナーの投稿待ち | `note/kaitori-shiire-sheet/` |

- 仕組み：商品は `src/notes.ts` で管理し、記事の frontmatter に `note: 'kaitori-sheet'` と書くと、本文の最後に案内が出る。**URL が空のあいだは何も出ない**ので、note に公開したら URL を入れるだけで全記事（WordPress にも）に反映される
- 自社商品なのでアフィリエイトではない（PR表記は付かない）
- Excel は `python note/kaitori-shiire-sheet/build_sheet.py` で作り直せる。判定基準の初期値は運営者の実際の設定
- note の投稿手順・価格・ハッシュタグは `note/kaitori-shiire-sheet/note_manuscript.md` の冒頭
- 販売数・高評価数は、公開前には予測できない（フォロワー・閲覧数の実績がないため）。公開後の閲覧数・購入数・感想で、価格と次の商品を決める

## 7. アフィリエイトリンクの管理

- 記事には `[表示テキスト](aff:ID)` と書く。ID と広告URLは `src/affiliates.ts` の1か所で管理する
- URL が空（未提携）のあいだは、リンクにならず表示テキストだけが出る。提携前から記事を書いておける
- ASP で提携が承認されたら、広告リンクの URL（A8.net は計測用画像の URL も）を `src/affiliates.ts` に入れるだけで、全記事のリンクが有効になる
- 提携済みリンクを含む記事には、PR表記が自動で付く。リンクには `rel="sponsored nofollow"` が自動で付く
- 登録されていない ID を書くと、ビルドがエラーで止まる

## 8. 記事の品質ルール

- 数字・手数料・規約は、根拠（公式ページ・運営者の実データ）がある内容だけ書き、確認日を入れる
- 体験談・実績は、オーナーから受け取った事実だけを書く。**作らない**
- アフィリエイトリンクを入れた記事は `pr: true`（PR表記が自動で出る）。リンクには `rel="sponsored"` を付ける
- 「誰でも稼げる」「確実に儲かる」などの表現は使わない
- 公開前に毎回、次を確認する：ビルド成功／スマホ幅（390px）で横はみ出しなし／計算ツールや表の数字の検算

## 9. ChatGPT との連携

- 連携ボード：Google ドライブの「ブログアフィリエイト収益化｜Claude×GPT 連携ボード」（このマニュアルの要約と、GPT からの受け渡し欄）
- 役割：Claude＝執筆・公開・ツール保守／GPT＝体験談インタビュー・競合調査・ブラウザー操作の補助
- GPT の成果は、ボードの受け渡し欄か Claude のチャットに貼る。Claude が事実だけを記事に反映する

## 10. Claude への頼み方

- 「次の記事を書いて公開して」→ 記事計画の上から順に、執筆・確認・push まで行う
- 「#4 を書いて。使っているカードは〇〇」→ 実データ付きで執筆
- 「今月の実績：仕入れ〇件、利益〇円」→ 月次実績記事を作成
