## 設計の柱

**一本道：Fact → 仕分け → 仮説 → 4S → 解決策（エリアプラン）**

- **Needs＝理想と現状のGap（状態）／Wants＝Gapを埋める具体的な手段**（ROTF3 顧客理解・意思決定能力）。
  顕在Needs・潜在Needsもここで扱う
- 情報を **Fact（事実）／Wants（手段）／Needs（状態）** の3つに分ける。判定の目安は
  「これは状態か、手段か」「願望が入っていなければFact」
- **ワーク①（10分）は2部構成**
  - 前半4分：ファシリテーターが提示する例題9件（腎臓内科の医局から得た情報。製品には紐づけない）を
    3つに仕分ける。スライド15の記入欄に番号を入れる形。答え合わせは付録A（各3件ずつの設計）
  - 後半6分：「先生のWantsから、Needsを汲み取れた経験はありますか？」を3〜4人で共有
  - 直後に付録B〜Dを投影し、「こんなことが考えられる」をワーク②の材料にする
- **ワーク②（10分）は 仮説 → 4S → 解決策 まで**。仮説の例5件・解決策の例5件を画面に残したまま進める。
  スライド21の4Sシート（成功像／現状・課題／原因／解決策）に、原因＝仮説、解決策＝打ち手として書き切る
- **4Sとの対応を明示**：Needs→成功像／Fact→現状・課題／仮説→原因／Wants→解決策の入口。
  スライド22に記入例を掲載
- **Triple Win（患者・顧客・自社）を Beyond（関連病院・近隣大学・地域の先生）まで広げる**
- **まとめは女子医大の活動**。初回面談の一言「女子医大腎臓内科を全国に売り出したい」＝Wants →
  「実臨床の経験を全国と地域に届ける場がない」＝Needs → 「女子医大をHUBにすれば横展開が起こる」＝仮説 →
  3大学＋院内（小児腎・移植）を企画段階から巻き込む設計 → 参加35名・処方確約1例・患者発掘1例・
  IC向上2施設・医師同士の関係性を複数確認
- ⑨総括は所長用の記入エリアを確保

## 付録

| | 内容 |
|---|---|
| A | ワーク① 仕分けの一例（各3件と、仕分けが割れることの意味） |
| B | 考えられるFact（施設・診療体制／患者・診療実態／人事・組織／教育・研究・学術／関係性／地域・外部環境 の6分類×5件＝30件。評価や推測を混ぜず事実として書く） |
| C | Wants → 複数のNeeds仮説 → 確認したい質問（12種のWants。講演会・外部講師・資料・若手教育・診療連携・患者紹介・研究論文・全国発信・医局人事・地域活動・大学間連携・院内他科連携をカバー） |
| D | 考えられるNeeds12件（手段ではなく状態で書く）＋ 考える型（Wants→複数仮説→質問→複数の解決策）＋ 解決策の広がり4層（一施設内／大学と関連病院／複数大学／エリア全体） |
| E | 4Sへつなげる思考プロセスの参考例×3（関連病院向け勉強会／全国発信／腎病理教育。起点Fact・Wants→仮説→質問→Success/Situation/Source/Solution） |
| F | ファシリテーター用メモ（進行／付録の使い方＝4S参考例はワーク前に投影しない／記録・書記） |

付録の設計原則：一つのWantsに一つのNeeds・一つの解決策だけを示さない。
分類の正解を覚えることではなく、「一つの発言にも複数の解釈があり、追加で確認する情報によって
仮説が変わる」ことを理解してもらうのが狙い。エリアプランの視点（大学＝エリアの1施設／HUB）は
本編のBeyond（12枚目）と付録Dの4層で扱う。
