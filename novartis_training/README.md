## 設計の柱

**一本道：Fact → 仕分け → 仮説 → 4S → 解決策（エリアプラン）**

- **ニーズ＝理想と現状のGap（状態）／ウォンツ＝Gapを埋める具体的な手段**（ROTF3 顧客理解・意思決定能力）。
  顕在ニーズ・潜在ニーズもここで扱う
- 情報を **Fact（事実）／ウォンツ（手段）／ニーズ（状態）** の3つに分ける。判定の目安は
  「これは状態か、手段か」「願望が入っていなければFact」
- **ワーク①（10分）は2部構成**
  - 前半4分：ファシリテーターが提示する例題9件（腎臓内科の医局から得た情報。製品には紐づけない）を
    3つに仕分ける。スライド15の記入欄に番号を入れる形。答え合わせは付録A（各3件ずつの設計）
  - 後半6分：「先生のウォンツから、ニーズを汲み取れた経験はありますか？」を3〜4人で共有
  - 直後に付録B・Cを投影し、「こんなことが考えられる」をワーク②の材料にする
- **ワーク②（10分）は 仮説 → 4S → 解決策 まで**。仮説の例5件・解決策の例5件を画面に残したまま進める。
  スライド21の4Sシート（成功像／現状・課題／原因／解決策）に、原因＝仮説、解決策＝打ち手として書き切る
- **4Sとの対応を明示**：ニーズ→成功像／Fact→現状・課題／仮説→原因／ウォンツ→解決策の入口。
  スライド22に記入例を掲載
- **Triple Win（患者・顧客・自社）を Beyond（関連病院・近隣大学・地域の先生）まで広げる**
- **まとめは女子医大の活動**。初回面談の一言「女子医大腎臓内科を全国に売り出したい」＝ウォンツ →
  「実臨床の経験を全国と地域に届ける場がない」＝ニーズ → 「女子医大をHUBにすれば横展開が起こる」＝仮説 →
  3大学＋院内（小児腎・移植）を企画段階から巻き込む設計 → 参加35名・処方確約1例・患者発掘1例・
  IC向上2施設・医師同士の関係性を複数確認
- ⑨総括は所長用の記入エリアを確保
