## 設計の柱

**一本道：Fact → 仕分け → 仮説 → 4S → 解決策**

- **Needs＝理想と現状のGap（状態）／Wants＝Gapを埋める具体的な手段**（ROTF3）。
  判定の目安は「これは状態か、手段か」「願望が入っていなければFact」
- **ワーク①（10分）は2部構成**
  - 前半4分：例題9件（腎臓内科の医局から得た情報。製品には紐づけない）を3つに仕分ける。
    13枚目の記入欄に番号を入れる。答え合わせは付録A（各3件ずつの設計）
  - 後半6分：「先生のWantsから、Needsを汲み取れた経験は？」を3〜4人で共有
  - 直後に付録B・Cを投影し、ワーク②の材料にする
- **A病院の事例（17・18・21枚目）**。17枚目は根拠の提示：病院ホームページ「実績」ページの表と、
  開業医向け広報誌の着任あいさつを、出典つきで引用（URL・施設名・氏名は伏せ字、年度は相対表記）。
  「面会の前に、公開情報だけでここまで分かる」＝DAY3のDry情報の実物。
  18枚目で読み解く。ある基幹病院で、新しい部長の着任年度に腎生検が36件→90件（約2.5倍）に増え、
  その後も96・99件で定着した実例。着任時に開業医向けの広報誌へ寄稿し「腎臓に問題がある患者様が
  いらっしゃいましたら、いつでもご紹介ください」と発信（＝Wants）。その裏の「透析を導入する医療ではなく、
  透析になる患者さんを一人でも減らしたい」（＝Needs）から、「地域の腎臓診療の入口を担おうとしている」という
  仮説を立てる。21枚目でその仮説を4Sに落とし、ノバルティスができること／患者WIN・顧客WIN・自社WINまで設計する。
  施設名・医師名は伏せ、年度は「着任2年前／着任年度／＋1年」の相対表記
- **ワーク②（10分）は 仮説 → 4S → 解決策 まで**。仮説の例5件・解決策の例5件を画面に残したまま、
  20枚目の4Sシートに書き切る
- **4Sとの対応**：Needs→成功像／Fact→現状・課題／仮説→原因／Wants→解決策の入口
- **Triple Win（患者・顧客・自社）を Beyond（関連病院・近隣大学・地域の先生・患者さんの流れ）まで広げる**
- **まとめは女子医大の活動**。一言のWants「女子医大腎臓内科を全国に売り出したい」→
  Needs「実臨床の経験を全国と地域に届ける場がない」→ 仮説「女子医大をHUBにすれば横展開が起こる」→
  設計と成果（参加35名／処方確約1例・患者発掘1例・IC向上2施設／医師同士の関係性を複数確認）
- 一つのWantsに複数のNeeds仮説。決めつけず、質問で確かめる
